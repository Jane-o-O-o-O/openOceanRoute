# 按 KP 范围检查纵坡与侧坡

`oceanroute.slope_rules.check_slope_rules(project, config=None, *, analysis=None, terrain_signature=None)` 是独立、只读的规则检查器。它按各条规则声明的 KP 区间报告实际采样超限、缺测、过期和来源边界不确定性。它不调整路线、余缆、制造装配、固定缆长或 Path Link 约束。此项属于冻结 0.8 之后的开发工作，本文不代表新版本发行、全套测试或海试验收。

## 公开依据与独立语义

用户提供的 MakaiPlan 6.2 手册物理 PDF 第 266 页／印刷页 258 的 Slope Rule 段落明确允许检查纵坡、侧坡或二者，并用 KP 范围限定路径的一部分，随后列出全部检查错误。物理第 107 页／印刷页 99 说明侧坡计算间距；第 111 页／印刷页 103 区分沿路径的底坡与左右侧坡；第 114 页／印刷页 106 规定向右舷升高的侧坡为正。可在仓库提取文本的 `=== PDF PAGE 266 ===` 等标记处核对。

这些公开资料确定了功能、范围与侧坡符号。它们没有公开本模块的原始探点校核、覆盖判定、规则 JSON、数值容差或缺测分类算法。本模块是独立实现；不读取原厂规则文件，不宣称原生格式或隐藏算法兼容。

本模块的 KP 是当前 `route.curve` 所定义 WGS84 水平路线距离，单位米，和实物电缆 KP、海底累计距离不同。阈值是角度，单位度，比较坡度**绝对值**。纵坡的记录方向是深度正向下；侧坡保留生产模块的“从左舷向右舷、升高为正”方向。绝对值规则无需把二者强行改成同一带符号定义。

## 保存字段与请求

规则保存在路径投影的 `project.slope_rules` 独立数组。每条规则只允许下列字段；未知字段、重复 ID、布尔数值、非有限数值和不适用的阈值均拒绝。

```json
{
  "id": "slope-zone-a",
  "name": "近岸坡度检查",
  "enabled": true,
  "kind": "both",
  "start_kp_m": 0,
  "end_kp_m": null,
  "max_inline_slope_deg": 15,
  "max_side_slope_deg": 12
}
```

`kind` 是 `inline`、`side` 或 `both`，分别要求纵坡阈值、侧坡阈值或两个阈值；不允许给单一类型添加另一个类型的阈值。阈值范围是 `0 ≤ θ < 90`。ID 为 1–128 字符的非空文字，名称为 1–256 字符，缺省名称取 ID。`enabled` 缺省为 `true`；关闭的规则仍校验声明格式，但无需读取对应坡度数据。

`start_kp_m` 缺省为 0，必须非负。明确的数值终点必须大于起点。`end_kp_m:null` 缺省且保存为 `null`，表示现在及以后路线的终点；不得把它静默固定为本次路线总长。结果同时给出声明 `requested_range_m:[start,null]` 与本次解析后的数值 `end_kp_m`。路线后来缩短，使此类规则起点达到或超过新终点时，保留规则并返回 `unknown`／`RULE_RANGE_EMPTY`，不使合法保存声明变成格式错误。数值范围超出路线的部分保持原声明、报告未知覆盖，不裁剪成通过。

`config` 只允许 `rules`、`max_rules`、`max_work_units`、`max_output_bytes`。显式 `config.rules` 覆盖本次检查用的规则，**不写回输入**；没有覆盖时使用保存清单。空数组返回 `not_configured`，全关闭返回 `disabled`。各条规则独立，宽松规则不会取消另一条规则的违例。

实际 HTTP 接线为：

```text
POST /api/tools/slope-rules
{project, config:{rules:[...], ...预算字段}}
```

API 返回本模块报告并附 `project` 候选，候选仅更新规范的 `slope_rules`，保留输入修订。单独调用 Python 检查器不返回候选。候选仍须通过工程的现有分析、约束、制造一致性和乐观修订校验后保存。核心仅在路径显式包含 `slope_rules` 时自动追加 `analysis.slope_rule_checks`，未带该字段的旧路径不增加这项检查结果。

侧坡的实际采样接口是 `POST /api/terrain/side-slopes {project,config}`；其来源、探点和预算详见 [SIDE_SLOPES_NOTES.md](SIDE_SLOPES_NOTES.md)。检查器不会自行创建新横断面，也不会把地图海图、零水深或纵剖面当作侧坡。

## 实际数值与覆盖判定

纵坡复用核心 `_profiles` 的绑定、NoData 与分段线性语义。没有导入剖面时，允许明确标记的 `waypoint_linear_approximation`；已经提供但过期或未绑定的剖面停用，绝不回退到偶然保留的路线点深度。来源库绑定剖面还必须匹配当前 `terrain_library_signature`。

对相邻有效深度 `(k₀,D₀)`、`(k₁,D₁)`，纵坡是 `degrees(atan2(D₁-D₀,k₁-k₀))`。检查该**整个原分段**与规则区间的正长度交集，违例记录使用相交后的起终 KP；不会因为分段起点位于规则之外而漏掉跨界部分。任何一端缺深度的分段不参与坡度计算，不跨缺测连接下一个有效点。纵坡的完整覆盖表示声明范围内的分段模型可用，不是连续实测床面已证明安全。

侧坡只使用根及 `metadata.model` 均为 `route-side-slopes-v1`、`schema_version:1` 的持久对象，并检查根 `route_signature` 和 `metadata.terrain_library_signature`。路线形状、曲线类型、地形内容、解释、启用或优先级改变后，旧数据返回 `unknown`，不会报告旧超限值为当前证据。可传入的 `analysis` 和 `terrain_signature` 是内部复用当前核心结果及已计算库摘要的参数；缓存结果绑定不符时拒绝，正确标记旧剖面不可用的当前结果则正常返回未知。

每站的原始 `transect` 必须有至少三个严格递增偏移探点，包含声明的左右端点与中心。检查器从相邻有效深度重新计算 `max_sampled_abs_slope_deg`，并复核半幅、全幅角及缺测语义；分类使用重新计算的值，避免持久化舍入摘要隐藏超限。任一半幅中间探点缺测时该半幅角必须为空；全幅只要含缺测也为空。相邻有效段仍可给出真实、明确不完整的超限证据。V 形截面即使全幅和两个半幅角抵消为零，最大相邻角仍参与规则检查。

站点 `complete` 必须与所有声明探点均有深度一致。有效探点有不同 `(source_id,source_fingerprint)`，即使被缺测隔开，或存在明确相邻来源边界，都不能隐藏 `source_boundary`。来源跳变可能由源数据的垂直偏移产生，故该站不认证为连续床面坡度。来源字面上声明同一基准也不等于测量精度一致。

侧坡检查只列规则闭区间内**实际站点**的超限，不插值生成横坡站。覆盖同时列出实际范围、域内站点、支持区间的相邻站点、缺测站、来源边界站及超过声明 `spacing_m` 的站距缺口。只有相邻完整且无来源边界、间距不超过声明值的站点区间才能覆盖规则范围。域内没有实际站点时不判通过，即使两边有站；单个真实横断面可给出超限证据，但不能覆盖正长度规则区间。

这里的区间覆盖是**采样网格覆盖**，不是站间插值坡度或整条海底走廊无危险的证明。未采样位置的细沟、尖峰或 NoData 可被漏过，`continuous_bed_verified` 始终为 `false`。

角度等于阈值不算超限。非零阈值附近只按最多 8 个浮点 ULP 处理几何计算的数值相等，不增加固定工程角度容差；零阈值对任何计算得到的非零坡度都超限。原始摘要复核使用 `1e-8` 度数值容差，但违例使用原始探点重建值。KP 覆盖合并与端点相等采用 `1e-7 m` 的数值容差。

## 返回状态与诊断

报告包含 `model:'kp-slope-rules-v1'`、`validation_status:'research'`、`rules`、`results`、`summary`、`metadata`、`warnings`、`budget`、`assumptions`。元数据给出实际路线签名、来源库摘要以及规范规则数组的 `rules_signature`；修改清单后旧规则报告不可继续当作当前结果。

每条结果包含 ID、名称、类型、声明 `requested_range_m`、解析 KP 范围、`components.inline/side`、完整 `violations` 和 `diagnostics`。状态含义如下：

| 状态 | 含义 |
| --- | --- |
| `disabled` | 关闭，不读取或检查坡度 |
| `sampled_pass` | 所需数据当前可用且声明采样域覆盖完整，无已采样超限；不代表连续床面通过 |
| `violations` | 至少一项真实已采样超限；仍可能同时有未知或不完整覆盖 |
| `incomplete` | 有可用数据，但缺测、来源边界、范围或站距覆盖不足 |
| `unknown` | 所需数据缺失、过期、无域内站点或当前无正长度可检查域 |

规则与整体汇总优先保留真实超限，其后才是未知、不完整及采样通过。**不要只看 `status` 判断完整性。** `components[kind].coverage.complete` 和 `summary.all_requested_data_available` 是覆盖指标；`summary.incomplete_rules` 在存在违例时仍计入覆盖不足的规则。侧坡还提供 `missing_kps_m`、`uncertain_kps_m`、`unknown_ranges_m` 和 `sampling_gaps_m`。每项侧坡违例的 `uncertain` 表示该站来源边界或缺测，不能借全局 `violations` 标签隐去不确定性。

纵坡违例有真实交集起终 KP、带符号角、阈值与分段索引；侧坡违例有真实站 KP、相邻采样最大绝对角、阈值、站索引与不确定标志。数据格式、数值和预算错误抛 `SlopeRuleError(ValueError)` 或既有校验 `ValueError`，由 API 返回 422；合法但缺测/过期的数据返回可显示的未知报告。

## 工作量和容量

| 限制 | 默认／硬上限 |
| --- | --- |
| `max_rules` | 默认 128，最大 512，整数至少 1 |
| `max_work_units` | 默认 5,000,000，最大 20,000,000，整数至少 1 |
| `max_output_bytes` | 默认 16 MiB，最大 32 MiB，至少 1 KiB |
| 路线点 | 2–10,000 |
| 原始纵剖面点 | 100,000；内部核心插入路线边界后的结果最多 110,000 |
| 横坡站／所有站累计原始探点 | 各最多 50,000 |

工作量先于库指纹解析和规则计算检查：路线与剖面预处理、探点处理、每条启用规则的相应采样比较分别按有界逻辑单位计入；返回 `budget.estimated_work_units`。这不是 FLOPs、硬时间或内存上限。地形源库的规范化／指纹解析另受该模块自身容量限制，未声称纳入本检查器全部逻辑工作量。额外 `analysis`／`terrain_signature` 可避免核心自动检查时重复进行已完成的预处理。

保留结果先保守计入输出预算，违例同时计入其警告副本；最终再测量实际有限、紧凑 UTF-8 JSON。预算不足拒绝整个报告，不删违例、不丢诊断、不自动减少站点。API／单独调用的只读检查默认 128 条，可显式上调 `max_rules` 至 512；该预算不保存到清单。核心自动检查显式使用 512 条上限，从而允许完整保存高于默认 128 条的合法清单，同时继续遵守默认工作量和输出预算。513 条及以上明确拒绝。

## 独立验收范围

`tests/test_slope_rules.py` 使用直接指定的分段剖面、真实 WGS84 距离和真实 Surfer 栅格，并对公开生产函数的结果进行独立分析。实际仿射深度 `D(x,y)=1000+0.2x` 上的北向路线具有平坦纵剖面而横坡绝对角为 `atan(0.2)=11.309932474°`：600 m 路线、100 m 沿线间距的七个站，侧坡阈值 10° 给七项超限，12° 给 `sampled_pass`。洞内低优先级来源回退即使全部角低于 89°，也返回来源边界不完整，避免把源接缝判为通过。

独立案例还覆盖 KP 双边裁剪、负纵坡和阈值相等、纵剖面脊线、全幅抵消的 V 形横断面、真实半幅 NoData、单断面、来源隔缺测跳变、规则相互独立、路线／内容／启用／优先级／基准失效、声明 null 终点重算、日期线高纬短航段、重复坐标深度冲突、浏览器 JSON 数值往返、原始摘要篡改、当前核心复用／旧缓存拒绝、制造输入逐字节不变及先行预算拒绝。

这些案例没有证明原厂算法等效、连续走廊安全、海底测量精度或 plow 的力学适用性。完整后端、浏览器、正式文档与发行验收由主线另行执行，不能把此处专项测试计数当作发布门禁。
