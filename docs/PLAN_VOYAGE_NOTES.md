# 规划、制造库存与连续敷设的显式映射

2026-10-04，独立研究实现。`oceanroute/plan_voyage.py` 提供 `prepare_plan_voyage(project, config)`；HTTP为 `POST /api/shipplan/prepare-voyage`，请求 `{project,config}`。输出包括实际初步船舶计划、可提交给 `/api/voyage/jobs` 的完整 `config`、校验过的 `mapping`、警告和适用假设。它准备明确的解析初始窗口，不重建真实已敷状态。

## 坐标、初始库存与放缆

路线KP来自WGS84曲线，制造库存位置来自内核SLD，船端动态材料坐标按自然长度递增。三者单独保存，额外allowance在固定路线KP上增加制造库存，停船和偏移调整时段可以不增加放缆。

初始动态悬垂段已经占用制造材料。程序按现有动态模型的同一解析节点、EA及预应力计算初始自然长度；默认从初步计划累计放缆量第一次达到该自然长度的计划时刻开始，制造原点为0。显式选择更晚的 `start_time_s` 时，原点等于船端制造位置减初始自然长度。配置中的 `initial_suspended_material_m` 是最老海床端的制造位置，名字不表示船端位置。此前放出量不会再次作为新放缆输入，也不伪称此前历史已经算过。

每个非零SLD cable/allowance区间对应真实 `material_segments`，同型同物性的相邻段可合并，原始区间对应关系仍保留。EA、湿重和直径须在电缆库明确给出；缺少干质量时，按全浸水圆截面排水量和湿重反推，并记录 `mass_source`。密度、声明的均匀海流和底张力与初步计划一致；动态可使用逐缆型阻力、分层流等更详细输入，初步偏移仍采用原计划的均匀稳态近似，需要复核。所有使用缆型的张力上限取最严格者、弯曲半径取最大者作全模型保守检查，不声称已做每一材料点的专用失效评估。

零长度附属体按内核已经校核的制造位置映射，必须提供 `mass_kg`、`wet_weight_n` 和 `drag_area_m2`；质量、湿重和阻力作为已有材料节点的形函数载荷。有限长度实体不会被填上虚构电缆材料：当前转换明确拒绝，仍需独立杆/承载模型。原制造表在实体区间的语义不能通过叠加一份缆重保持正确。

## 地理指令与初态

以窗口开始时的实际初步船位作为局部AEQD投影原点。每个船舶指令截取至窗口边界，保留其原放缆率；局部船速和艏向由投影后端点距离/原时长计算，使动态积分到达明确的局部端点。半段位置与投影弦中点的实际误差必须不超过声明容差；这是一项采样误差检查，不是任意长地理曲线的严格误差界。超范围、超指令数或投影检查失败均拒绝。

初始缆形是同物性的解析悬链线，初始速度为零。它不是有流稳态或已敷调查重建；系统不会为贴合目标底路线而强行移动初始锚点。`initial_anchor_xy_m` 与 `planned_start_touchdown_xy_m` 分别记录两者，`initial_target_touchdown_residual_m` 显示实际差值。该初态偏差和启动瞬态仍需解释，不能用船位/材料守恒证明触地点已沿规划路线施工。

当前要求完整、有效、向下为正的定深平海床剖面，以及初始悬垂材料区间同物性。不同水深不会静默改成平床。后续放缆可进入混合缆材和转弯；原动态模型、平床安全粗化以及实际求解预算的限制仍适用。正长度实体、不同物性的初始悬垂区间、制造库存之外的操作员额外放缆、缺失物性/测深均拒绝，要求补充真实数据或新的物理模型。

## 配置和保存

```json
{
  "plan": {"sample_spacing_m": 30, "bottom_tension_n": 10},
  "duration_s": 10,
  "simulation": {"nodes": 16, "dt_s": 1, "internal_dt_s": 0.05, "solver_iterations": 24},
  "voyage": {"chunk_duration_s": 3, "adaptive_mesh": {"enabled": false}}
}
```

`start_time_s` 可选，表示源船舶计划中的时刻；动态局部时钟从0开始。`duration_s` 必须正且不超过源计划剩余时间。`max_track_span_m` 默认100000米，最大1000000米；`projection_tolerance_m` 默认0.1米。初始材料段、深度、放缆、航向和时间指令由规划映射拥有，`simulation` 不能再独立覆盖。通过 `simulation` 显式配置数值参数、海流、升沉及海况仍须满足基础求解器条件。

准备结果的 `config.plan_mapping` 必须随任务提交。它保存项目SHA256、路线签名、源/局部时间、初始与最终制造位置、完整区间对应、源动态输入和校验值。改变工程或动态输入后必须重新准备；JSON整数/浮点等值的校验语义一致。该校验用于一致性，不是原厂授权或数据真实性证明。

每个完整分块保存前检查实际船端材料坐标与映射时间的制造预算一致。结果及外层voyage检查点保留原映射；保存和恢复都核对实际物理参数/材料位置。恢复请求如提供非空工程，必须与保存的项目摘要相符；空工程 `{}` 表示仅按保存快照离线恢复，不意味着已校核当前编辑中的工程。子任务可在选定窗口内继续，超过预备终点拒绝；不能把终止后的零放缆控制当作下一段施工已经有规划。历史窗口和真实状态应保留，再针对有校核的未来控制扩展模型。

## 实际验证

`tests/test_plan_voyage.py` 用实际动态结果核对初始库存不重复放出、全部材料船端位置、船位端点、allowance固定KP、转向和混合物性、点实体实际加载、完整检查点与续算一致、输入过期/损坏拒绝及HTTP流程。10米水深的10秒示例实际新增放缆5.1米；初始约12.23844米悬垂材料单独计入库存。测试不证明有流平衡、复杂海底、实体完整动力或全航程工程精度。相关基础合同见 `SHIPPLAN_NOTES.md`、`VOYAGE_NOTES.md`、`MODEL_NOTES.md`。
