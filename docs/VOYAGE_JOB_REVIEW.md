# 长航程后台任务的独立完整性审查

审查日期：2026-10-04。范围为 `oceanroute/voyage_jobs.py`、`api.py` 的 voyage 接口及其持久化/并发边界；没有修改数值模型、任务模块或 API 源文件。数值粗化、工程精度和全航程有效性由单独审查负责，下面的任务完整性证据不能代替它们。

新增 `tests/test_voyage_jobs_integrity.py` 使用真实 VoyageJobs、真实 run_voyage/动态求解和实际 checkpoint 读取。只在文件发布或调度边界注入故障；没有用伪造数值、空模型或装饰性成功结果。两种中断试验使用真正的子进程 `os._exit`，跳过 Python 清理路径。

## 首次审查结论与修复状态

首次基线包含18个用例：9个通过、9个发现待修缺口；不得当作最终发行回归通过记录。这里记录初始复现，修复后的状态应以下文回归记录为准。

| 优先级 | 原实现位置与实际问题 | 复现证据/需要满足的不变量 |
| --- | --- | --- |
| P1 | `VoyageJobs.__init__` 没有任务目录单 owner 保护，第二服务直接重写第一服务活跃状态 | 真正的第二 Python 进程成功取得同目录，原运行任务被改为 interrupted；需要非阻塞跨进程锁，第二实例明确拒绝，不能恢复/取消第一实例的工作 |
| P1 | 分块 checkpoint 发布后、status 发布前退出，重启只改状态字符串 | 子进程在 checkpoint.json 已原子发布时退出；重启存在有效0.4 s断点，但 checkpoint_available 仍 false、completed_chunks/进度过期；必须读取和验证实际文件重建旗标与进度 |
| P1 | 最终 result 已发布、终态 status 尚未发布时退出 | 实际完整0.8 s结果存在，重启却只报 interrupted/result_available=false；应校核有效最终结果及断点后恢复真实终态，而不是隐藏完整成果 |
| P1 | `cancel` 只检查 cancellations map，终态发布与 worker finally 清理之间仍可取消 | 在真实 completed 状态发布窗口提交 cancel，状态被改为 cancelling，worker随后仅移除事件，永久无新终态；终态取消必须幂等，只允许 active 状态转换 |
| P2 | `close` 后 submit 仍创建请求/状态/事件，再在 executor.submit 失败 | 真实任务结束并close后再次submit，出现永不运行的queued目录；必须先检查closed再创建任何持久实体，初始化/调度失败也应回滚或标记真实失败 |
| P2 | UUID验证之后仍跟随目录/JSON文件symlink，启动/list遍历也不限定 canonical UUID | UUID目录指向外部目录时get能读外部status；合法任务result.json指向外部JSON时也可被下载；应拒绝目录/文件symlink、检查根目录边界，只扫描合法任务目录 |
| P2 | 一个损坏status.json使整个管理器和create_app无法启动 | 保留一个真实健康已完成任务，再写入另一个损坏状态文件，重启抛JSONDecodeError；应隔离/报告坏任务，健康任务和服务仍可读取 |
| P2 | `_write` 只fsync临时文件，rename后没有刷新父目录 | POSIX实际fsync观察没有目录调用；文件完整原子替换不等于目录项在掉电后耐久，应刷新目录并说明非POSIX/文件系统差异 |

两个断点恢复问题由不同用例覆盖，目录和文件symlink也分别覆盖，所以待修用例数量为9。UUID文本拒绝只能证明普通路径穿越输入不被使用，不能代替symlink根目录约束。Symlink试验针对本地任务目录受损/被修改情景，没有宣称HTTP接口可以远程创建任意链接。

上述缺口已由任务/API模块负责者修复。本审查随后补入关闭期间的跨进程锁保持、损坏状态字段类型、任务数及磁盘额度、删除和降低额度后读取恢复等用例；最终完整性集为25项，全部通过。该结论限定于下文列出的测试边界，不能推导为所有文件系统和数值场景已经认证。

## 初次已经通过的实际行为

- 目标文件rename失败，原已发布JSON保持完整可读，没有半写状态取代旧内容。
- 单实例一位worker和四个active/queued上限有效；第5个任务在创建目录前拒绝。
- 排队任务取消后没有计算帧、没有虚构checkpoint，computed_duration_s为0；其他真实任务继续完成。
- 最终result写入模拟磁盘失败时，任务如实failed，真实最后checkpoint仍可校验并继续到正确绝对时间。
- 非canonical UUID、路径分隔符和`../`不能选择任务文件（4个参数化用例）。
- 超过32,000,000字节或含NaN的请求在创建任务目录前拒绝。
- 实际HTTP覆盖对象结构、缺失/非法任务ID、真实result/checkpoint下载及普通终态取消。有效结果是有限JSON，最后帧及断点时间均为请求结束时间。

## HTTP与生命周期核验范围

| 接口 | 当前职责 |
| --- | --- |
| `POST /api/voyage/run` | 同步真实计算，请求 `{project,config}` |
| `GET/POST /api/voyage/jobs` | 列表/提交后台任务；结构合法但物理参数非法可作为后台failed返回，不能伪造完成 |
| `GET /api/voyage/jobs/{job_id}` | 状态、进度和文件可用旗标 |
| `POST /api/voyage/jobs/{job_id}/cancel` | 完成块边界取消；不能声称当前内部积分已经立即中止 |
| `POST /api/voyage/jobs/{job_id}/resume` | 从有效最后完成状态创建新任务，保留parent_job_id；只允许续算时长/输出/工作预算等公开选项 |
| `GET /api/voyage/jobs/{job_id}/checkpoint` | 读取、实际验证voyage/物理checkpoint |
| `GET /api/voyage/jobs/{job_id}/result` | 已发布实际结果；不存在为404 |
| `DELETE /api/voyage/jobs/{job_id}` | 显式删除非活跃且worker已经退出的任务及其全部目录文件；不能删除正在计算/排队/取消中的任务 |

API的FastAPI lifespan负责启动和close；全局`app=create_app()`采用lazy初始化，纯import不取得任务目录owner锁。启动时取得非阻塞跨进程锁，POSIX使用flock、Windows使用msvcrt字节锁；目录已被另一实例占用时明确拒绝。初始化失败释放已取得资源。

close发出取消并拒绝新提交，等待全部writer退出后才释放owner锁；真实子进程试验证明等待期间另一实例不能取得同目录。取消在真实计算块完成边界响应，关闭会等待正在计算的块和必要文件写入；数值计算或存储缓慢时退出也会延迟，没有硬实时停止期限。已发布终态后的重复取消保持终态，避免永久cancelling。

重启读取并验证实际checkpoint和result，重建旗标、已完成块数和进度；仅有有效断点的活跃任务恢复为interrupted，已有有效最终结果的任务恢复真实终态。断点文件缺失/无效时可从有效result内嵌断点读取。损坏的状态JSON或必要状态字段被隔离，其他健康任务仍可读取。任务目录扫描仅接受canonical UUID真实目录，读取/写入拒绝目录及文件symlink。

## 输入、输出及磁盘总量的限制

修复后采用以下限制，字节均指有限JSON序列化后的字节数：request为32,000,000、checkpoint为16,000,000、result/其他普通文件为64,000,000；status独立限定64,000，重启接受的result摘要限定32,000。读取文件先检查大小并拒绝非有限JSON。同步`POST /api/voyage/run`也在返回前检查结果不超过64,000,000字节。数值模块另有限制duration、chunk数量、保留帧数、工作量及mesh历史。不同限制不能混为事前内存或物理磁盘硬额度保证：

- 结果体积在构造/序列化之后检查，超限前可能已经消耗计算和内存；长航程优先使用后台任务与公开输出/工作预算。计算过程中仍可能到最终发布才触发文件限制，实际最后有效断点保留，可按额度继续处理。
- 默认单目录逻辑数据额度为1,000,000,000字节、最多250个保存任务；单worker、最多4个活跃/排队任务。新request在额度不足时拒绝且不留下孤立目录；已有任务结果发布超额时报failed，不覆盖其他结果。显式DELETE非活跃任务后释放额度，不会自动删除历史。
- 逻辑额度统计canonical任务目录内普通文件，并预留`min(1,000,000, quota/10)`字节供元数据；这不是文件系统物理容量硬限制。原子替换期间旧文件与新临时文件可同时存在，需要额外瞬时空间，磁盘本身仍可能写满。
- status单独按64,000字节约束，管理员降低额度至小于已存历史后仍允许恢复状态、list/read/checkpoint/DELETE，不因旧数据超额锁死服务；不自动删除旧成果，新的数据写入拒绝直到释放空间。元数据写入与既有超额历史是逻辑额度的明确例外。
- 原子写使用同目录随机独占临时文件、文件fsync、rename，POSIX再fsync父目录。断电遗留的临时文件也可能占用空间；删除对应非活跃任务会一并移除。没有将应用额度等同于操作系统配额。

此审查没有用超过内存或磁盘容量的大型计算做破坏性压力测试。macOS/POSIX上的真实进程退出、互斥和目录刷新已验收；真实掉电、网络文件系统及Windows锁/刷新没有实机认证。本地受信任用户可修改任务目录的情景仅验证静态损坏/链接拒绝，不宣称抵御同权限恶意进程在每个文件系统检查与操作之间的竞态。
