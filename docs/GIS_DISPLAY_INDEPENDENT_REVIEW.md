# GIS 图层显示与 S-57 接线独立审查

审查对象为本轮开发源码，不修改冻结的 0.7 发行文件。审查者：独立规划/验收代理。本文记录源码审查、实际 Python 工作区操作及已执行的独立浏览器用例；不把专项或有失败的全量首轮称为发行验收。

## 范围与发现

审查 `api.py` 的 S-57 三个 multipart 入口，以及 `S57ImportPanel`、`App`、`EmptyWorkspace`、`useWorkspaceDocument`、`LayerManager`、`MapView`、`ProjectedMapView`、`layerDisplay` 和已有 `layer-display.spec.ts`。原生 S-57 数值、更新链和持久来源证据的独立验收另见 [S57_INDEPENDENT_REVIEW.md](S57_INDEPENDENT_REVIEW.md)。这里的重合线为明确声明的合成显示测试数据，不冒充海图或测量成果。

已发现并向主代理报告两项实际差异，当前源码已修复：

1. 原经纬地图对每个要素施加不透明度，投影视图对整个图层施加不透明度。同层两条完全重合、不透明度均为 0.5 的线，在前者交叠处产生 `1 − (1 − 0.5)² = 0.75` 的线条覆盖率，后者为整层 0.5。当前 `MapView` 将一个 GeoJSON 图层的全部实际 SVG 路径移入单一 `<g opacity>`，保持路径自身 stroke opacity 为 1、面填充为 0.14、点填充为 0.2；投影视图维持整层分组。
2. 合法旧工程可以省略 `visible`：实际迁移和物化保留该字段缺省，后端地图投影按可见处理；原经纬地图的布尔过滤和复选框却按隐藏处理。当前 `layerVisible` 统一将 `undefined` 解释为可见，同时保留显式布尔值。显示或保存不需要向源图层补写 `visible`。

新增独立用例 `web/tests/layer-opacity-independent.spec.ts` 仅一项，覆盖同层重合线、缺省可见性、两种真实地图、分组清理、真实保存/重开及源数据守恒。用例只拦截明确的初始合成样例；迁移、工程分析、投影、SQLite 保存和重开均调用实际后端。该项已在实际生产构建上首次通过，耗时 3.012 秒、零重试；随后也在 87 项全量首轮中通过，耗时 2.923 秒。原始记录分别为 `resources/validation/development_0.8_gis_specialist_browser.json` 和 `development_0.8_final_browser.json`，执行/输入记录见同前缀的 `execution.json`。

全量首轮实际为 85 通过、2 失败、零跳过及重试，总耗时 268.338371 秒；另外两项失败发生在 S-57 修订恢复和旧工作区新建/改名流程，不是本独立用例通过就消失的失败。专项原三项运行也保留了另一个投影显示用例因画布高度改变造成绝对屏幕 `d` 比较失败的记录。此处只记录本项真实通过，不宣称全部浏览器或发行已通过。

## 接线与原子性核对

- 三个 `/api/import/s57/{inspect,catalog}` 与 `/api/import/s57` 入口共用上传校验：`config_json` 必须为有限 JSON 对象、禁止重复键和非有限数值，并有 32 KiB 配置限额；文件有实际读取上限。原生解析转入工作线程，校验错误返回 422。没有把解析出的测深 Z 自动写入工程地形或制造长度。
- S-57 面板将文件身份、目录/对象类选择、名称、预算和完整工程上下文纳入预览有效性，校验阶段间文件摘要，拒绝迟到结果。解析成功只是可审查预览，仍需显式应用全部所选图层。
- `App.applyS57Layers` 在真实 `update_shared` 返回后再次核对完整文档对象、工程身份、修订和面板快照；通过后才一次替换工作区并加入撤销历史。路径、制造实体和关联没有由导入回调重新构造。空工作区的独立弹窗也只在原子应用返回成功后关闭，不制造虚构路线。
- 实际 Python 操作分别覆盖共享装配的两条备选路径、活跃路径投影的显示修改，以及无路径但保留库存的空工作区。修改图层顺序/不透明度或加入显式图层后，路径、装配、关联、材料库、地形源库与活跃路径保持原值，源输入对象未被就地修改。

## 显示、签名与 Leaflet 生命周期

图层数组尾部在最上方；管理器反向列出数组，操作使用副本并保留 GeoJSON、来源和未知字段。透明度只存在于 `display.opacity`，不修改坐标、测深、材料和制造量。

投影视图的计算签名包含真实已分析路线曲线、控制点、GIS 几何/属性、可见性、CRS 和预算。图层按 ID 排序计算，因此仅叠放次序和透明度变化不丢弃有效 XY；绘制时从当前工程读取顺序和不透明度。真正的几何变更会改变签名。只影响来源说明的 metadata 不被误作几何输入。异步计算和点编辑均有序列、上下文及卸载核验，未发现本轮新增的旧几何响应应用入口。

实际安装的 Leaflet SVG renderer 保留 `_path` 引用：重设坐标和样式直接更新该路径，交互目标绑定到该路径；移除操作直接移除路径并解除绑定，不要求它仍直接位于原 root group。当前整层分组保留路径节点和事件冒泡，重绘先 `clearLayers()` 再移除并清空旧分组引用。路线、路线点和经纬网没有被归入 GIS 不透明度分组。安装源码核对以及上述实际浏览器用例均确认两条完整 stroke 共用单一 0.5 分组、各 stroke 自身不透明度为 1；真实重绘、地图重新挂载与保存重开后未出现重复 GIS 分组。
