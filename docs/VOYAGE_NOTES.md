# 长时连续铺缆计算与后台恢复

`voyage.py` 对真实材料节点状态作分段延续，`voyage_jobs.py` 提供本地后台任务。结果始终为研究模型；这项扩展允许部分工况突破原来256节点的短窗口上限，没有完成原厂全航程、复杂海底与实船精度认证。公开范围参考 [MakaiPlan Pro](https://www.makai.com/cable-software/makaiplan-pro/)，方程和原动态模型的假设见 [MODEL_NOTES.md](MODEL_NOTES.md)。

## 计算与材料坐标

每个chunk调用同一个实际动态求解器，以完整checkpoint恢复位置、速度、自然长度、局部物性、海床接触、原锚点、船舶边界、绝对指令时钟和累计放缆量。未用输出帧猜测速度，也没有把旧尾缆删除或触地点改成新的固定锚点。所有自然长度和原固定锚点始终留在活动模型中。

`simulation` 接受原动态模型参数。坐标是局部米制X/Y/Z，北0°、顺时针艏向，Z向上。材料坐标从最老海床端向船端增加。普通配置中规划经纬度、表面KP、制造SLD与动态材料坐标不自动互换；用户须提供明确的施工控制、物性、材料分段与实体参数。未填写的缆型参数可依原动态API从所给Project首段/所选缆型继承；可复核的合成例子应写全参数，避免随工程库变动。

0.3可显式调用 `/api/shipplan/prepare-voyage` 从实际路线、SLD和缆库准备定深平床施工窗口；返回完整simulation和plan_mapping，后者必须随任务保留。它把初始已悬垂库存与新增放缆分开，并在每块/保存恢复时校核实际材料船端位置。非空工程须匹配准备/保存摘要，空工程恢复明确只采用保存快照；超过准备窗口拒绝。初始锚偏差如实显示，不把解析零速度初态当作实敷重建。模型与输入限制见 [PLAN_VOYAGE_NOTES.md](PLAN_VOYAGE_NOTES.md)。

绝对船舶指令表在首chunk初始化后随checkpoint延续。如果预先提供超出本次请求的未来指令，应声明足以覆盖它们的`simulation.ship_plan_horizon_s`。恢复任务保留全部物理配置，允许更改请求时长、输出数量和计算预算，不静默更改物性、设备控制或海流；改变工况可使用既有Look Ahead/动态分支功能。

## 有条件的海床网格粗化

粗化仅删除一个内节点并将相邻两个自然长度元相加，保留两端真实位置，重新积分材料载荷。只允许平海床、同一均匀材料区间、零EI、远离实体和材料边界、船端、触地点与原锚端的元素。非平床仍可连续计算，但此粗化策略拒绝，不将变化地形降成平床。

每个内部时间步和chunk起始状态都有不可修改的诊断副本。三个候选节点必须在整段检查时间内始终接触海床且低速，并至少满足默认2秒稳定窗。证据记录实际内部采样数、时间段和稳定的材料坐标集合；没有证据不能自动粗化。

近直线并不足够。算法还检查被删材料点按合并后的自然长度比例重建的位置变化，默认不超过0.001m；比较带符号的几何轴向应变，不能把不同压缩量都截成0后当作等价。湿重、干质量、等效质量、自然长度和线动量积分必须保持；被删节点动量按两邻节点实际新增的等效质量转移。新张力由新几何/EA/自然长度的正伸长计算，不能简单平均旧力。动能、轴向弹性能、质心位移和角动量缺陷另行报告。

每批候选还真实运行原网格与候选网格的短时双解。比较全部旧材料位置在粗网格上的重构、保留节点、速度、触地点、顶底张力、内部峰值、接触状态和数值收敛。失败则保留原状态。局部probe和逐删除容差不是全航程累计误差界，也不证明海试精度；完整误差仍需独立细网格对照。审计含完整before/candidate checkpoint、内部步证据、每次转移和probe。

## 请求、工作量与输出上限

`POST /api/voyage/jobs`接收`{project,config}`，返回真实任务ID；只允许一位后台计算者及至多四个运行/排队任务。`config`主要参数：

| 参数 | 默认及范围 | 含义 |
|---|---|---|
| duration_s | 3600；正值，至多30天 | 本次请求的继续时长，不保证预算内算完 |
| chunk_duration_s | 30；0.02–600秒 | 单段上限，按节点/步数/工作量缩短 |
| max_total_work_units | 120,000,000；至多2,000,000,000 | 本次主算和粗化探针预算 |
| max_chunks | 2000；1–10000 | 本次已完成chunk数量上限 |
| max_output_frames | 512；2–4096 | 保留真实输出帧上限；保留首尾并抽稀，不合成帧 |
| max_mesh_records | 64；1–128 | 保留完整粗化审计的上限 |
| adaptive_mesh.target_nodes | 96；12–220 | 目标而非保证；不安全时保留细网格 |

原求解器每段仍限制256节点、30,000内部步、12M工作单元等。主算在剩余预算中预检；两个探针分别受半数剩余预算约束，波浪工作也通过真实求解器预算检查。工作单元是程序的规模估计，不是token、CPU指令数或墙钟时间；失败探针无法确定实际工作时保守扣除其声明上限，并单列`failed_probe_budget_charge`。

完整voyage checkpoint至多16MB，粗化历史至多12MB，单任务输入至多32MB，最终结果至多64MB。后台缓存默认数据配额1GB、至多250个保存任务；实际运行还需足够磁盘临时空间。降低配额不自动删旧结果，仍可读取和删除已结束任务，新增数据会被拒绝；恢复元数据另有64KB单文件上限。`DELETE /api/voyage/jobs/{id}`只允许已结束且无活动写者的任务。删除不会修改规划工程。同步`/api/voyage/run`也限制64MB最终JSON，但没有后台持久化，长计算应使用jobs。

## 状态、取消、崩溃与恢复

查询`GET /api/voyage/jobs/{id}`获得状态及实际进度。`completed`表示算到本次请求终点；`stopped`表示工作量、节点或审计容量达到上限，只完成部分；`cancelled`停止于完整chunk；`failed`给出实际异常；进程骤停后重建为`interrupted`。这些状态不能显示成已完成全请求。

`POST /{id}/cancel`请求停止，完成当前chunk后保存状态。`GET /{id}/checkpoint`和`GET /{id}/result`读取真实JSON。`POST /{id}/resume`传`{duration_s,...输出/预算选项}`创建新任务，记录parent_job_id，从旧任务的实际绝对时间继续。无checkpoint的排队取消或预算零进展不能恢复。

任务文件使用有限JSON、随机独占临时文件、文件fsync和原子replace；POSIX另对父目录fsync。重启根据真正的checkpoint/result重建旗标、时间和完成数量，不仅依赖可能尚未更新的status。损坏状态隔离，不阻止健康任务读取。规范UUID、目录与文件symlink限制避免从任务ID越出缓存目录。

非阻塞操作系统目录锁限制同一缓存只有一个服务写者，锁保持到全部工作线程退出。未启动的API对象不抢锁；第二服务必须使用原服务或另一个`OCEANROUTE_DATA_DIR`。不能把不同端口当作同数据目录的并行计算者。Windows锁/文件路径有实现，但当前实际耐久、并发与崩溃验收在macOS完成；文件系统、断电、存储硬件及网络盘仍需专门验证。

## 实际验证及局限

连续chunk与未粗化单次真实模型、绝对时间恢复、取消、有限预算、实际HTTP后台任务、落盘读取和故障恢复均有测试。独立物理测试用完整细网格的所有材料点作双向对照，另核对实际保存数组的质量/长度/动量，而不只相信审计数字。详细结果见 [VOYAGE_PHYSICS_REVIEW.md](VOYAGE_PHYSICS_REVIEW.md)；目录并发、真实子进程骤停、故障落盘、配额与删除验收见 [VOYAGE_JOB_REVIEW.md](VOYAGE_JOB_REVIEW.md)。

一组明确的浅水平床无流算例实际连续计算1800秒，放缆1080m，完成60个chunk、1184次内节点合并，最后117个活动节点；长度平衡残差约7.3×10⁻¹⁰m，各chunk数值约束收敛，局部完整材料probe最大位置差约3.78×10⁻⁵m，本机42.12秒。配置及真实摘要在`resources/validation/voyage_1800s.json`。这是该工况的计算证据，没有相同1800秒完整细网格或独立求解器全程误差基准，不能套用到深水、横流、变地形或海试。

现有限制包括固定初始锚端、全浸水近似、平床粗化、有限窗口边界、局部米制场、既有接触摩擦/弯曲近似，以及缺少实船控制/测量同化。节点无安全合并机会时会明确停止，不降低门槛或生成虚构帧。完整三维海底、球面长路线到动力材料的受校核映射、实体六自由度、原厂原生文件、长期工程误差及海试对照仍未完成。
