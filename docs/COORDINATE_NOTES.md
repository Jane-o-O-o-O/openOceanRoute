# 显式水平坐标转换与路线编辑

0.4开发功能；独立PROJ运算，不读取或复刻原厂CSF文件。公开手册的投影/坐标编辑用于功能需求对照；地图仍使用WGS84地理视图，当前并未实现整张地图的任意投影切换。

`POST /api/coordinates/transform` 输入如下，接口只生成预览，不修改或保存工程：

```json
{"source_crs":"EPSG:32650","target_crs":"EPSG:4326","points":[{"id":"p1","x":603224.6404290784,"y":2433164.428653589}],"error_policy":"collect"}
```

该例返回经度118°、纬度22°。坐标必须按CRS原生单位填写，X/Y顺序明确：地理坐标为经度/纬度，投影为对应横向/纵向轴。声明度、grad、米或英尺会参与真实转换，不能靠数值猜单位。输出的`axis_units`提供轴名、方向和单位换算因子。西向经度、南向纬度和非Greenwich本初子午线按实际声明处理。路线内部始终存WGS84十进制度；深度不会参与此转换。

只支持二维地理/投影水平CRS，拒绝地心、垂直、复合和三维坐标。需要明确EPSG或合法WKT/PROJ文本（最多16,384字符）；不自动解析原厂CSF，不接受高度、速度或工程其它字段。每批1–10,000点，id可省略，提供时须唯一且1–128字符。NaN、Inf、布尔、字符串数值、超范围经纬度或非法字段成为明确坏点。

默认collect保留每点输入、成功/错误、实际输出及`operation_index`；任何坏点均令`can_apply=false`，成功部分不会自动写入路线。reject在首个坏点抛错。全局无效CRS/字段/批量超限返回422。不同基准按各点地理适用区选择操作，`operations`保留实际使用的方法；相同基准的投影批量复用同一操作。无非ballpark方法、或声明地区最佳操作需要未安装网格时拒绝该点，不能静默退回近似基准变换。PROJ网络状态照实记录，不自动更改用户全局网络设置。最佳网格可用性和数值取决于实际安装的PROJ数据库与网格。

CRS/操作适用区之外的点显示`COORDINATE_OUTSIDE_AREA`警告；数学输出可供核对，不代表当地测量精度。`accuracy_m=null`表示PROJ未声明精度，不能改成零；该精度是操作声明，不是测量误差上限。地区选择先由源CRS本身的地理位置构造范围，基准位移可能影响适用区边缘的判断。来源资料的基准及精度仍需用户核实。

界面可在路线点资料打开投影坐标编辑，也可在工程工具输入多点，读取当前WGS84坐标反转换至源坐标系。先预览并核对轴单位、适用区、真实坐标及错误，然后明确应用。输入、选中点或当前工程变更会使旧预览失效。普通路线保持现有修改/撤销流程；已有制造域约束的点须经真正的约束编辑求解，预览展示求解后的实际位置，固定滑动点不开放XY直改。投影转换不会绕过制造量、Path Link或共享库存校核。

验证包含真实UTM已知值及正反转换、原生英尺与grad、真实NTF Paris本初子午线、西/南向轴、不同输入错误、缺最佳网格分支及真实HTTP无工程副作用。仍没有与原厂、测量控制点或实船数据对照。

依据：[pyproj Transformer/TransformerGroup官方文档](https://pyproj4.github.io/pyproj/stable/api/transformer.html)，[PROJ坐标操作官方说明](https://proj.org/en/stable/usage/transformation.html)。
